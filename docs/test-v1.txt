七、已知限制与环境说明
----------------------------------------------------------------
1. 弱网下行（入向）限速需 ifb 内核模块支持。测试机 ColorOS 精简 ROM
   未加载 ifb，且未 Root，故 hasIfb=false；代码已实现 ifb + ingress
   重定向路径，在支持环境可生效。
2. 上行 netem 需要 Root（su）。测试机未 Root，因此 E2E 只验证了
   「探测能力」与「预设读写」，未实际下发 tc 规则。
3. 保底方案：未 Root 时可用「整体断网」开关（svc wifi/data disable）。
4. ColorOS 精简 ROM 无 ip 命令，网络接口列表走 /proc/net/dev 兜底解析。

九、踩坑记录
----------------------------------------------------------------
1. ELECTRON_RUN_AS_NODE 陷阱
   本机 agent 环境注入了 ELECTRON_RUN_AS_NODE=1，导致 electron.exe 以
   纯 Node 模式运行，require('electron') 返回路径字符串而非 API 对象，
   报错 "Cannot read properties of undefined (reading 'whenReady')"。
   解决：在 bash 中 unset ELECTRON_RUN_AS_NODE 后再启动。
   PowerShell 的 Start-Process -Environment @{ELECTRON_RUN_AS_NODE=$null}
   无效（仍继承），必须用 shell unset。

2. 侧栏高亮"滞后一页"是测试假象
   直接改 window.location.hash 绕过了 React Router 的更新时序。
   改用 loadFile(file, {hash}) 逐页重新加载后 9/9 正确。

3. TS 语法雷区
   shared/types.ts 中误写 raw-only 非法标识符 → 改 rawOnly
   weaknet.ts 正则字面量混入路径斜杠 → /tc/ 简化
   AppliedRule.cleanup 是 string[]，误包一层中括号变成 string[][]

4. 编译产物中 handler 用 IPC.XXX 符号引用
   冒烟脚本早期按字符串 'app:detail' 查找全部失败，改为匹配常量名。
