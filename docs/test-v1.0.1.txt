三、需求 ②：免 Root 弱网（代理式）
================================================================

实现方式
----------------------------------------------------------------
  手机 App ──► 手机 127.0.0.1:17890 ──adb reverse──► 电脑代理（注入弱网）──► 真实服务器
                       ▲
           settings put global http_proxy 127.0.0.1:17890   （免 Root）
                       │
           ROM 禁止写设置时 → UI 切「手动代理向导」，用户去 WLAN 里手填

  新增 electron/services/proxy-shaping.ts（代理 + 整形引擎）：
    · 上行 / 下行各挂一个整形器，7 参数（带宽/延迟/抖动/丢包/错报/乱序/重复包）
    · 延迟/抖动/带宽精确（定时投递 + 令牌桶，带宽用令牌桶而非 netem 的 rate）
    · 丢包 = 队头阻塞等效（命中后延迟一个 RTO 并拖住后续），**绝不丢字节**
    · 乱序 = 附加抖动等效（投递时间单调不减），**绝不打乱字节顺序**
    · 错报 = 真篡改字节；重复包 = 按 (1+dup) 折算有效带宽
    · 大块按 16KB 切片计费；限速时对来源 socket 背压（1MB / 256KB 水位）
    · 停止时先投递完队列再 end()（destroy() 会丢发送缓冲 → 响应截断）

  weaknet.ts 扩展：
    · probeWriteSettings() 实测 ROM 能否 adb 写系统设置
    · 代理模式：能写就自动写 + 读回确认；不能写则 manual=true，tickProxy()
      每秒轮询 settings get global http_proxy，用户填好后自动识别生效
    · 崩溃恢复：会话标记 userData/weaknet-session.json，异常退出后下次启动自动
      清代理 + 恢复网络；正常退出走 will-quit 拦截清理
    · probeDevice() 能力卡片增加「adb 写系统设置」一行

修复「找不到启动键」
----------------------------------------------------------------
  旧版：没配任何参数时按钮 disabled + start() 直接 return → 用户看到一个灰按钮，
        反馈「不知道怎么实现 / 没找到启动键」。
  现在：有设备就能点；未配置参数自动套用默认弱档
        （下行 1Mbps · 延迟 300ms±80ms · 丢包 1%），并 toast 告知。


四、弱网代理端到端测试（scripts/e2e-weaknet-proxy.cjs）
================================================================
  用法：node scripts/e2e-weaknet-proxy.cjs            只跑 Stage A
        ADB_SERIAL=xxx node scripts/e2e-weaknet-proxy.cjs --device

  Stage A · 引擎级（19 项，纯 Node，不起设备）             19/19
    Node 客户端经代理请求本地源站，逐项量化：
    基线 / 下行延迟 500ms / 上行延迟 400ms / 双向叠加 /
    带宽 0.5Mbps / 丢包 40% ×5 轮 / 错报 100% / 乱序 50% /
    重复包 100% / 组合档位「2G弱网」/ CONNECT(HTTPS) 隧道 / 统计重置

  Stage B · 设备链路（18 项，真机）                        18/18
    经 adb reverse + 免 Root 代理，从设备侧打到电脑源站。

  —— 真机合计 37 通过 / 0 失败
  —— 模拟器 emulator-5556：35 通过 / 0 失败（浏览器驱动不了 → 应用级 2 项如实 SKIP）

真机实测数据（都是量化对数，不是"看着生效了"）
----------------------------------------------------------------
  | 项 | 结果 |
  | --- | --- |
  | 设备经代理基线 | 15ms / 13 字节 / HTTP 200 |
  | 下行延迟 600ms | 15ms → 611ms（+596ms） |
  | 上下行叠加 400+400 | 813ms |
  | 下行带宽 0.5Mbps（200KB 理论 3277ms） | 3161ms |
  | 丢包 50% 不截断 | 收到 204800 字节（完整） |
  | 全局代理写入读回 | 一致 127.0.0.1:17890 |
  | **真实浏览器经系统全局代理** | 源站收到请求（启动到命中 2777ms） |
  | **应用级弱网（3s 上行延迟）** | 代理侧实测 1624ms → 3020ms |
  | **手动代理路径：系统代理为空** | 读回 null（证明不靠全局代理） |
  | **手动代理路径：显式走代理可达** | 12ms / HTTP 200 |

  最后三项是为 ROM 禁写设置的机型补的：模拟受限 ROM 用户的真实操作 ——
  系统代理为空，靠「设备 loopback → adb reverse → 电脑代理」打通，
  证明手动向导那条路上通道、代理、弱网注入三件事都成立，

七、本轮踩到并写进 README 的坑
----------------------------------------------------------------
  1. 测试脚本里 spawnSync 会阻塞事件循环，把「自己」的代理服务一起卡死
     —— 代理跑在测试进程身上，spawnSync 期间无法 accept()，设备侧表现为
        「TCP 连上了但 60s 无响应」（RC=28 / time_total=60001ms），极像防火墙。
        指纹：同脚本里 spawnSync 的那几项全挂、纯异步的那几项全过。

  2. adb shell 传参必须整体加引号：adb 用空格拼接参数，
     `-w '%{a} %{b}'` 会被设备 shell 拆成 3 段，后两段当 URL 解析 → 空输出。

  3. 设备 shell 的 curl 不读 Android 全局代理设置（实测 RC=7），
     所以「全局代理对 App 生效」只能用真实应用验证（系统浏览器 + 源站命中计数）。

  4. 测延迟必须注入在上行：请求走上行，只给下行加延迟的话请求照样瞬间到源站。

  5. Electron 测试脚本 app.exit() 后进程不退出，挂住父 shell；
     杀 shell 又留下僵尸 electron 进程，占着默认 userData 目录让后续脚本卡死。
     → 新增 scripts/run-electron.py：输出重定向到文件 + 独立 --user-data-dir +
       超时强杀 + `--watch/--until` 看到日志完成标记就主动收工（并判定 PASS/FAIL）。
       效果：导航脚本 10.6s 收工，真机脚本 11.8s 收工，不再白等 150~240s。
