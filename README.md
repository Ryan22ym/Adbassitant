# ADB 桌面助手 v1.1.6

一个用 **Electron + React + TypeScript** 写的 Android 设备管理工具。
把日常调试要用的东西收进一个界面：设备管理、投屏、应用与安装包、日志、弱网模拟、连点器 —— 不用在命令行和一堆小工具之间来回切。

- **平台**：Windows 10/11 x64（使用者）
- **设备**：Android，需开启「开发者选项」与「USB 调试」
- **形态**：只出 NSIS 安装包，支持应用内增量更新

### 弱网模拟：五种实现方式

UI 上可选，默认「自动」= **首选 VPN，装不上退回本地代理**。

| 方式 | 原理 | 前置条件 |
| --- | --- | --- |
| **VPN**（默认，免 Root） | 设备侧配套 App（`com.xiaoyang.weaknetvpn`）起 `VpnService` 建 tun，在 **IP 层全量整形**（真丢包、真乱序、真限速）；电脑经 `adb forward tcp:18080` + HTTP 控制 | 只需 USB 调试；未装 App 时尝试自动安装；**覆盖所有 App 的流量** |
| **本地代理**（回退，免 Root） | 设备流量 → `127.0.0.1:17890` → `adb reverse` → 电脑代理进程注入弱网 → 真实服务器 | 只需 USB 调试；**只覆盖会走 HTTP 代理的流量** |
| **tc/netem** | `tc qdisc … netem`（上行 `root`，下行 `ifb` + `ingress`） | 需 Root + 内核 `ifb` |
| **整体断网** | `svc wifi/data disable` | 免 Root，只能全断 |
| **手动代理向导** | 同「本地代理」，代理地址由用户去设备 WLAN 设置里手填 | ROM 禁止 `adb` 写系统设置时自动切换 |

> 为什么默认不用代理：代理只拦得到「愿意走系统代理」的流量，游戏、走原生 socket 的 App 直接绕过，表现为「弱网没效果」。VPN 在 IP 层工作，覆盖全量流量，代价是首次要往设备装一个几 MB 的配套 App。
>
> 验弱网必须走 UI 的真实链路（启动 / 状态 / 停止）。裸 `adb forward` + 直发 `POST /start` 会因建隧道的真空期被误判成失败；`adb shell` / 设备上的 `curl` 也测不出效果（shell uid 不进 VPN）。

### 在线更新：为什么用外部助手

运行期间 `resources/app.asar` 被独占锁定（`os.replace` → WinError 5、`rename` → WinError 32），连「再起一个自己的实例来替换」都不行。所以更新交给系统自带的 PowerShell 助手（不落地自制 exe，避免被杀软拦）：

```
应用：prepareUpdate(zip) 解压 + 逐项校验 → applyUpdate() 停投屏/Logcat/弱网 + 停 adb → 写 job.json
     → 由系统代建助手（不能直接 spawn，否则会被应用的作业对象连坐杀掉）→ app.exit(0)
助手：等主进程退出 → 等文件解锁 → 备份 → 原子替换 → 启动新版 → 轮询健康标记（≤30s）
        ├─ 出现 → 成功（保留备份，界面出现「回滚到 vX」）
        └─ 没有 → 杀新版 → 还原备份 → 启动旧版 → 写 last-error
新版：渲染层就绪后发一次 IPC 握手 → 主进程落健康标记 → 读结果 → toast 提示
```

**「启动成功」的判据是渲染层握手，不是「主进程还活着」** —— 否则主进程活着但白屏会被判成成功，而那正是最需要回滚的情况。

发布走纯静态托管（`latest.json` + 各版本 zip，无后端），部署后必须用 HTTP HEAD 核对真实 key 与 size。

### 一条功能是怎么长出来的

新增功能的固定路径，五处都要动，缺一处就不通：

```
services/xxx.ts 写业务（只依赖 Node）
   → shared/types.ts 加类型与 IPC 通道常量
   → electron/preload.ts 暴露给渲染层（通道字面量两处必须同步）
   → src/pages/XxxPage.tsx 调 window.adbApi.xxx()
   → src/components/layout.tsx 加导航项（需要的话）
```

### 设计要点

- **分层解耦**：`services/` 只依赖 Node，不碰 Electron UI；`ipc.ts` 只做转发。
- **契约先行**：所有跨进程类型集中定义在 `shared/types.ts`，前后端共用，避免各写一套。
- **统一错误处理**：主进程 `wrap()` 把异常转成 `{ ok, data, error }`；渲染进程 `call()` 统一拆包 + toast，页面只写成功路径。
- **日志即基础设施**：所有 adb 调用都走 `runAdb()`，自动记录命令、耗时与输出，与「一键导出」天然打通。
- **纯逻辑独立成文件**：安装包归类规则放 `shared/packages.ts`，不 import `fs` —— 主进程要用、界面要预览、验收脚本要直跑，三边共用且能被渲染层打包。
- **设计系统**：颜色 / 圆角 / 阴影全部走 CSS 变量，深浅色与 5 套主题色只需覆盖变量表。
- **主题色管到窗口标题栏**：Windows 原生标题栏不跟应用主题色，所以用 `titleBarStyle:'hidden'` 自绘顶部带子，底色由侧栏色与内容区色 `color-mix()` 混出的第三档。回传主进程前须先归一成 `#rrggbb`（`getComputedStyle` 会把 `color-mix()` 序列化成 `color(srgb …)`）。高度三处必须一致，且**只能比系统标题栏高、不能更矮**。
