v1.0.19: 拆包与安装分离，.apks 可另存复用

以前「装 AAB」把 build-apks 与 install-apks 绑死在一次调用里：每换一台设备、
每重装一次都要重跑几十秒的拆包。现在拆成两个动作：

- AAB -> .apks：「仅拆包并另存为 .apks」按钮，可按当前设备配置拆一次、
  存成文件；同一个 AAB + 同一颗设备 + 同一份签名的产物走缓存，秒回。
- .apks -> 设备：直接吃现成产物，只跑 install-apks，不再拆包（输出里
  不会出现 build-apks / device-spec 字样）。

实现要点：
- aab.ts 抽出 convertBundle()（拆包 + 另存，不碰设备侧状态），
  installBundle() 改为「设备侧准备 -> convertBundle() -> install-apks」；
  新增 installApksFile()，只做安装。
- .apks 是 zip（toc.pb + splits），里面不含包名，而「装完按包名复核」
  是对 APK/AAB 一贯的硬规矩 -> 拆包时在产物目录写 source.aab.txt 记下源
  AAB 路径，装现成 .apks 时反查包名；更早版本的老缓存没有这个文件，
  退化为「不复核 + 打一条 warn」，不影响安装。
- 另存先写 .part 再 rename，中途失败不在用户目录留半截包。
- 装现成 .apks 绝不偷偷重拆：否则用户会以为装 .apks 比装 .aab 还慢。
- 覆盖 / 清洁 / 全新三种安装方式、装后复核在多包(.apks)路径上完全沿用。

通道与界面：
- 新通道 aab:convert / aab:saveApks / apks:install（ipc.ts、preload.ts、
  shared/types.ts 的 InstallKind 增加 'apks'）。
- install.ts 的 kindOf() 识别 .apks（排在 .apk 之前判），拖放区、
  文件选择器、安装弹窗（data-install-kind="apks"）、ToolsPage 全部打通；
  APKS 用绿色 kind-chip 与 AAB 区分。
